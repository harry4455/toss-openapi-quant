# 백테스트 검증 개념 가이드

백테스트 결과를 "믿어도 되는지" 판단하는 두 도구 — **파라미터 민감도 분석**과
**walk-forward 분석** — 을 개념부터 정리한다. 코드는 `src/validation.py`(전략 무관 엔진),
실행은 `src/validate_cli.py` / `src/momentum_cli.py` 참고.

---

## 0. 왜 필요한가 — "한 번 좋았다"의 함정

단일 구간 백테스트에서 +329%가 나왔다고 좋은 전략이 아니다. 그 구간이 **우연히
유리했을(표본 편향)** 수 있기 때문이다. 예: 2024~2026 구간은 삼성전자가 폭등한
특수한 장이라, 어떤 전략을 넣어도 좋게 나올 수 있다.

검증의 목표는 단 하나:
> **"이 수익이 실력(전략)인가, 운(그 구간)인가?"**

---

## 1. 파라미터 민감도 분석 (Parameter Sensitivity / Sweep)

### 개념
전략의 **설정값(파라미터)을 바꿔가며** 결과가 얼마나 달라지는지 본다.
- 듀얼 모멘텀의 `lookback`(모멘텀 측정 기간: 3·6·9·12개월)
- 이평선 DCA의 `ma_window`(이동평균 일수: 20·60·120일)

### 무엇을 읽나
- **결과가 파라미터에 따라 크게 출렁이면 → 위험 신호.**
  "12개월일 때만 좋고 11개월이면 망함" 같은 전략은 실전에서 그 값이 계속
  맞으리란 보장이 없다. 이를 **과최적화(overfitting)** 라 한다.
- **여러 파라미터에서 고르게 괜찮으면 → 견고함(robust).**

### 실제 사례 (듀얼 모멘텀)
| lookback | 수익률 |
|---|---|
| 3개월 | +521% |
| 12개월 | +329% |

편차 192%p. → 파라미터 의존이 너무 커서 "3개월이 정답"이라 단정하면 안 된다.
*주의:* 짧은 lookback은 워밍업 데이터가 적어 테스트 구간이 더 길어지는 교란도
섞이므로, 숫자 자체보다 "출렁임의 크기"를 본다.

## 2. Walk-Forward 분석

### 개념
하나의 고정 구간이 아니라, **테스트 창(window)을 시간순으로 조금씩 굴리며**
여러 구간에서 반복 검증한다. 각 창은 독립된 "한 번의 실전"이라고 보면 된다.

```
전체 데이터: [=====================================================]
창1:         [warmup][ test ]
창2:            [warmup][ test ]
창3:               [warmup][ test ]
...                  (step 간격으로 이동)
```

- **warmup(워밍업)**: 모멘텀·이평선 계산에 필요한 과거 데이터. 이만큼 지난 뒤부터
  실제 매매/평가가 시작된다.
- **horizon(창 길이)**: 한 창에서 성과를 측정하는 기간 (예: 6개월).
- **step(이동 간격)**: 다음 창으로 며칠 옮길지 (예: 1개월).

### 무엇을 읽나
각 창의 수익률을 모아 **분포**로 본다:
- **플러스 비율** — 몇 %의 창에서 수익이 났나 (높을수록 일관적)
- **벤치 초과 비율** — 단순보유(동일비중 buy&hold)를 이긴 창 비중
- **표준편차** — 결과가 들쭉날쭉한 정도 (클수록 운에 좌우됨)
- **평균 vs 중앙값** — 아래 3절 참고

### 실제 사례 (듀얼 모멘텀, 6개월 창 19개)
- 플러스 79% / 벤치초과 79% → 일관성 양호
- 단, 2024-09~12 **4연속 손실** → 하락 전환장에 약함(휩쏘)
- 표준편차 60%p → 변동성 큼

---

## 3. 해석할 때 흔한 함정 두 가지

### (a) 겹치는 창 = 자기상관 (Overlapping windows)
step이 horizon보다 짧으면 창들이 서로 **겹친다**. 겹친 창들은 같은 가격 흐름을
공유하므로 **독립된 표본이 아니다.** 강세장이 후반에 몰려 있으면, 그 구간을 겹쳐
포함하는 여러 창이 동시에 좋게 나와 "일관돼 보이는 착시"가 생긴다.
→ 창 개수가 많다고 그만큼 신뢰도가 오르는 게 아니다.

### (b) 평균(mean) vs 중앙값(median)
소수의 대박 창이 **평균을 끌어올린다.** 분포가 한쪽으로 치우치면(skew)
평균은 과장된다.
- 사례: 평균 +51% vs 중앙값 +26% → **중앙값이 더 현실적인 "보통의 결과".**
- 평균만 보고 기대치를 잡으면 실망하기 쉽다.

---

## 4. 데이터 길이와 표본 크기

- 검증 신뢰도는 **데이터가 길수록(여러 시장 국면을 포함할수록)** 올라간다.
  상승장만 담긴 2년 데이터로는 하락장 성능을 알 수 없다.
- 토스 candles는 1회 200봉, 페이지네이션으로 더 받음(`get_candles`가 자동 처리).
  단 rate-limit(429)이 있어 **캐시(`src/cache.py`)** 로 재사용한다.
- 이상적으로는 **여러 번의 강세·약세·횡보**가 들어간 기간(수년~10년+)으로 검증.

## 5. 신호 성과 추적 (이벤트 스터디)

전략 전체가 아니라 **신호 하나의 예측력**을 따로 검증하는 도구. (`src/signal_eval.py`)

### 개념
"매수 신호(이평선 아래 / RSI 과매도)가 뜬 날 이후, 주가가 **아무 날보다** 더 오르는가?"
- 과거 일봉에서 신호가 떴던 모든 날을 찾는다.
- 각 신호일의 **N일 후 수익률**(forward return)을 집계 → 신호일 평균.
- 같은 기간 **전체일 평균**(baseline)과 비교.
- **edge = 신호일 평균 − 전체일 평균.** edge>0이면 신호에 타이밍 예측력이 있다.

### 왜 전략 백테스트와 따로 보나
DCA 백테스트가 "이 전략 굴리면 얼마 버나"라면, 이건 "신호 자체가 똑똑한가"다.
이평선 DCA가 일반 DCA를 이겨도, 그게 **신호의 예측력** 때문인지 **현금 적립·재투입
타이밍** 같은 기계적 효과 때문인지 구분해준다.

### 읽을 때 주의
- **baseline이 높으면 edge가 음수여도 절대수익은 +.** 상승장 데이터에선 "아무 날이나"가
  이미 좋아서, 신호가 그걸 못 이기는 경우가 흔하다. edge는 "평소 대비 초과"일 뿐.
- 신호일이 몰리면 forward window가 **겹쳐 자기상관**(과대평가 가능).
- **자산마다 다르다** — 분산된 지수 ETF는 dip-buying의 평균회귀 edge가 크고,
  개별주는 약하거나 음수일 수 있다(계속 빠질 수 있으므로).

---

## 6. 요약 체크리스트

전략을 "쓸 만하다"고 판단하기 전에:
- [ ] 파라미터를 바꿔도 결과가 **무너지지 않는가** (민감도 sweep)
- [ ] 여러 시간 창에서 **꾸준히** 플러스/벤치초과인가 (walk-forward)
- [ ] **하락장·횡보장** 창에서도 버티는가
- [ ] 평균이 아닌 **중앙값**으로 기대치를 잡았는가
- [ ] 겹치는 창의 **자기상관**을 감안했는가
- [ ] 데이터가 **여러 국면**을 포함할 만큼 긴가
